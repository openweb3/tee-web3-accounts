# tee-web3-accounts

基于 TEE 的 Web3 账户托管服务, 使用 TEE 加强账户安全性。

TEE 核心负责安全地存储和管理用户的私钥，并在受信任的执行环境中执行所有签名操作。

整体 feature 如下:

1. TEE 启动时支持配置一个助记词
2. 核心提供两个接口:
   1. 创建账户地址: 入参是密码, 输出: 地址, 地址索引或路径 (TEE内部不需要存储私钥(实时计算), 只需要存储索引和密码的对应关系)
   2. 查询账户地址: 入参是索引, 输出: 地址
   3. 签署交易: 入参是密码, 需要签名的 hash, 账户索引, 输出: 签名

---

## 设计要点

**私钥从不落盘，也从不加密存储，而是每次用到时现场算出来。**

- 所有私钥由 TEE 启动时配置的一个助记词派生。任意索引对应的私钥都由
  `BIP-39 助记词 → 种子 → BIP-32 CKDpriv → 私钥` 这条纯函数链路当场算出，
  签完立刻抹掉（`PrivateKey.Zero()`），进程退出即消失。
- 持久化的只有三样东西：账户索引、地址、密码验证子。磁盘上不存在任何私钥材料，
  也就不存在「加密私钥的密钥往哪放」这个更难的二次问题。
- **密码只用于身份校验，不参与密钥派生。** 所以换密码不会改变地址；密码在存储层
  是 Argon2id 单向派生值，库文件泄露也拿不到密码。
- 地址会一并存一份，作用不是省计算，而是给助记词当**一致性护栏**：
  启动时逐个重新派生并比对，换错助记词会立刻拒绝启动（见下面的「启动护栏」）。

派生规则（全部按公开标准，可被任何钱包复现）：

| 环节 | 规则 |
|---|---|
| 助记词 → 种子 | BIP-39，PBKDF2-HMAC-SHA512，2048 轮，64 字节 |
| 账户路径 | BIP-44 以太坊路径 `m/44'/60'/0'/0/{index}`，最后两段非硬化 |
| 私钥 → 地址 | 未压缩公钥去掉 `04` 前缀后的 Keccak-256（原始 Keccak，非 SHA3-256）取后 20 字节，EIP-55 混合大小写 |
| 签名 | secp256k1 可恢复 ECDSA，RFC 6979 确定性 nonce，输出 65 字节 `r‖s‖v`，`v = 27 + recovery id` |
| 密码验证子 | Argon2id，t=3、m=64 MiB、p=4、32 字节输出、16 字节随机盐 |

## 接口

所有接口都是 JSON，默认只监听 `127.0.0.1:8080`。

### 1. 创建账户

```
POST /v1/accounts
{"password": "correct horse battery staple"}
```

`201 Created`

```json
{
  "index": 0,
  "path": "m/44'/60'/0'/0/0",
  "address": "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266"
}
```

索引由服务端顺序分配，客户端不能指定。密码至少 8 个字符、最多 1024 字节。
响应里不含私钥——私钥既没有被生成出来返回，也没有落盘。

### 2. 查询地址

```
GET /v1/accounts/{index}
```

`200 OK`，字段同上；索引不存在返回 `404`。地址是公开信息，**这个接口不需要密码**。

### 3. 签署交易

```
POST /v1/sign
{"index": 0, "password": "correct horse battery staple", "hash": "0x1111...1111"}
```

`hash` 是 32 字节的待签名哈希，接受带或不带 `0x` 前缀的 64 位十六进制字符串。
本服务只签哈希，不负责组装交易、也不做 EIP-191 / EIP-712 的封装。

`200 OK`

```json
{
  "index": 0,
  "path": "m/44'/60'/0'/0/0",
  "address": "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
  "hash": "0x1111...1111",
  "signature": "0x0f7ab7fd...b751b"
}
```

`signature` 是 `0x` + 130 个十六进制字符（65 字节 `r‖s‖v`，`v` 为 27/28）。

### 4. 健康检查

```
GET /healthz  →  {"status": "ok"}
```

### 状态码

| 码 | 含义 |
|---|---|
| `400` | 请求体不是合法 JSON、含未知字段、密码不符合策略、hash 不是 32 字节 |
| `401` | 索引或密码不正确（两种情况**返回完全相同的响应**，不给出探测信号） |
| `404` | 查询的索引不存在 |
| `405` | 方法不被支持 |
| `503` | 并发密码校验已打满，响应带 `Retry-After` |
| `500` | 内部错误，或助记词与账户库不一致 |

## 配置

全部通过环境变量注入，没有任何带默认值的密钥类配置。

| 变量 | 默认 | 说明 |
|---|---|---|
| `TEE_MNEMONIC` | **无，必填** | BIP-39 英文助记词。不配或配错（词数/词表/校验和不对）都拒绝启动 |
| `TEE_MNEMONIC_FILE` | 无 | 从文件读助记词，与 `TEE_MNEMONIC` 二选一。生产推荐用这个，避免助记词出现在进程环境里 |
| `TEE_MNEMONIC_PASSPHRASE` | 空 | BIP-39 可选的额外口令，**和用户密码无关** |
| `TEE_ACCOUNT_ROOT_PATH` | `m/44'/60'/0'/0` | 账户根路径，账户索引接在它后面 |
| `TEE_LISTEN_ADDR` | `127.0.0.1:8080` | 监听地址。默认只绑回环，不要直接暴露到公网 |
| `TEE_DATA_FILE` | `data/accounts.json` | 账户库文件路径 |
| `TEE_MAX_CONCURRENT_UNLOCKS` | `4` | 并发密码校验上限 |

`TEE_MNEMONIC` 和 `TEE_MNEMONIC_FILE` 同时设置会直接报错，不会猜用哪个。

## 启动护栏

这套系统最危险的故障是**静默派生出一整套不同的地址**：服务照常启动、照常响应，
但所有用户的资产都不再可达。启动路径上做了三层拦截，任何一层不过都拒绝启动：

1. **助记词合法性**：词数必须是 12/15/18/21/24，每个词必须在 BIP-39 英文词表里，
   校验和必须匹配 —— 拦住打错字的情况。
2. **助记词 ↔ 账户库一致性**：把账户库里每条记录的地址都用当前助记词重新派生并比对，
   换错助记词会在启动时直接失败并指出是哪个索引不匹配。
3. **助记词必填**：没有配置就没有默认值 —— 给助记词兜底默认值等于把所有人的资产
   交给一个公开的种子。

运行期间 `GET /v1/accounts/{index}` 也会现场重新派生地址并与库里那份比对，
把「不可能发生」变成可检测。

## 安全边界与已知限制

**保护的：**

- 私钥从不出现在磁盘、日志和 HTTP 响应里，只在 TEE 进程内存中存在极短时间。
- 账户库文件泄露只暴露地址（本来就是公开的）和 Argon2id 验证子，不暴露密码和私钥。
- 助记词换错、配错、缺失都会在启动阶段失败，不会带病提供服务。

**不保护的（务必了解）：**

- **助记词就是全部。** 任何拿到助记词的人都能离线重算出所有索引的私钥，与用户密码
  强弱无关。这是 HD 钱包的固有性质，也是 TEE 必须守住助记词的原因。
- **密码是唯一凭据，且索引是公开的。** 不需要任何认证就能枚举索引对应的地址，
  所以密码是唯一挡住签名的东西。Argon2id（64 MiB / 3 轮 / 并发上限 4）只是把离线
  爆破的成本抬高，不能替代密码强度。
- **服务自身没有客户端认证，也没有限速。** 只有并发上限（超出回 `503`）。
  生产部署必须把监听地址收在 TEE 内网，前面放一层带鉴权的反向代理和限速。
- **没有改密码 / 重置密码的接口。** 因为私钥与密码解耦，忘记密码不会丢地址、也不会丢
  私钥，但当前版本没有提供重新绑定密码的路径。需要时应通过带管理员鉴权的运维通道处理，
  而不是加一个无认证的公开接口。
- **只支持英文助记词。** BIP-39 要求先做 NFKD 归一化，英文词表全是 ASCII，
  归一化是恒等变换；其他语言词表需要额外的归一化依赖，当前不支持。
- 单机单进程，账户库常驻内存 + 整体原子落盘。账户数量到十万量级时应改成数据库。

## 本地运行

```bash
./run.sh test          # go vet + go test ./...
./run.sh build         # 编译到 bin/tee
./run.sh dev           # 用 Hardhat 测试助记词在 127.0.0.1:8080 起服务
./run.sh e2e           # 端到端测试：编译真实二进制、起进程、打全套接口
```

`dev` 用的助记词是 `test test test test test test test test test test test junk`
（Hardhat / Anvil 的公开测试助记词），对应的地址公开已知，因此可以直接对码验证：

## 测试覆盖

- `internal/wallet`：BIP-39 官方向量种子、Hardhat 与官方向量的多索引地址对码、
  EIP-55 规范测试向量、签名确定性、`RecoverAddress` 往返、路径解析、助记词校验的正反用例。
- `internal/store`：索引顺序分配、明文密码不入库、随机盐、密码校验、重开进程后的持久化与
  索引续接、创建失败不污染状态、助记词变更检测、损坏文件拒绝加载、并发创建不重号。
- `internal/api`：三个接口的完整正反用例、错误响应不泄露密码、错误响应不区分
  「索引不存在」与「密码错误」、未知字段 / 超大请求体 / 多段 JSON 拒绝、背压 `503`、
  方法限制、响应字段集精确匹配。
- `internal/e2e`：编译真实二进制起进程，跑完整业务流、重启后的持久化，以及
  「换错助记词必须拒绝启动」「没配助记词必须拒绝启动」「助记词校验和错误必须拒绝启动」
  三条护栏。
